# Файлы настроек eViSTool на машине с сервером

[English](config.md) · **Русский**

Всё, что агент eViSTool хранит о сервере, лежит в папке `data` рядом с `eViSTool.Agent`. Если туда писать нельзя,
eViSTool берёт запасную папку: `~/.local/share/eViSTool` на Linux, `%LOCALAPPDATA%\eViSTool` на Windows. Команда
`setup` такого не допускает и просит отдать папку eViSTool пользователю, от которого работает агент.

Пути ниже даны от папки `data`. `<профиль>` в именах файлов — id профиля: у агента без окна это `server` (или то, что
записано в `Profile` в `agent.json`), у профилей окна eViSTool — их собственные id.

Почти все эти файлы пишут окно eViSTool и сам агент, но их можно поправить и руками. Несколько правил:

- Файлы в формате JSON, кодировка UTF-8. Комментариев JSON не знает: свою заметку запиши отдельным полем, например
  `"Note": "…"`. В `agent.json` команда `setup` такие поля сохраняет.
- Правь от того же пользователя, от которого работает агент: `sudo -u vintagestory nano data/agent.json`. Файл,
  сохранённый от root, агент потом не сможет перезаписать.
- Ошибку в `agent.json` агент покажет и не запустится. Если же испорчен любой другой файл, агент молча возьмёт
  значения по умолчанию: с опечаткой в `automation.json` копии по расписанию перестанут делаться. После правки
  загляни в окно eViSTool или в консоль сервера.
- Агент читает `agent.json` только при запуске (после правки перезапусти агента или службу). Расписание, объявления и
  удалённый доступ он перечитывает на ходу, примерно раз в пять секунд. Настройки оповещений и отметку о сборе
  статистики он смотрит перед каждой отправкой и записью.
- Окно сохраняет файл целиком: если в окне открыта вкладка с теми же настройками, при сохранении она запишет то, что
  видит сама, и правка руками пропадёт.

## data/agent.json — агент без окна

Этот файл пишет команда `setup`, а читает агент, когда его запускают без окна (на Linux так всегда). Окно на Windows
передаёт агенту папки само, и тогда `agent.json` не читается.

```json
{
  "GameDir": "/home/vintagestory/server",
  "DataDir": "/var/vintagestory/data",
  "Profile": "server",
  "StartServer": true,
  "ServerName": "",
  "ServerArgs": [],
  "Language": ""
}
```

| Поле | Что это | Если пусто или поля нет |
|---|---|---|
| `GameDir` | Папка игры сервера, в ней лежит `VintagestoryServer.dll` | агент ищет сам: рядом с собой, в соседних папках, по `server.sh`, в `/home/vintagestory/server` |
| `DataDir` | Папка данных сервера (его `--dataPath`): мир, моды, `serverconfig.json` | из `server.sh` этой игры, иначе папка игры по умолчанию (`~/.config/VintagestoryData`) |
| `Profile` | Профиль агента. От него зависят имена всех файлов в `agents/` | `server` |
| `StartServer` | Запускать ли сервер вместе с агентом | `true` |
| `ServerName` | Имя сервера для резервных копий (`<имя>-2026-10-09_17-51-32.vcdbs`) и для заголовков оповещений, если окно не задало своё | `ServerName` из `serverconfig.json`, а если нет и его, копии называются `world-…` |
| `ServerArgs` | Дополнительные аргументы сервера, по одному в элементе списка | без них |
| `Language` | Язык сообщений агента и объявлений игрокам в чате: `ru` или `en` | язык системы; у службы systemd это обычно английский |

Каждое значение агент берёт из ключа командной строки, а если ключа нет, из `agent.json`. Папки, которых нет и там,
он ищет сам. Ключи: `--game`, `--data`, `--profile`, `--arg`, `--start` и `--no-start`, `--lang`. Например,
`./eViSTool.Agent --data /var/vintagestory/test` возьмёт игру из `agent.json`, а данные другие.

Пути лучше писать полностью. Относительный путь считается от папки, где лежит `agent.json`, а `~/` означает домашнюю
папку пользователя, от которого работает агент.

В имени копии знаки, которых не бывает в именах файлов, и пробелы становятся `_`: из «Survival Island» получится
`Survival_Island-…`. Ротация удаляет только копии со своим именем. Если имя сменить, старые копии останутся в списке,
но удалять их по расписанию агент уже не будет.

`setup` можно запускать повторно. Он обновит папки (и то, что передано ключами: `--profile`, `--name`, `--arg`,
`--start`, `--no-start`), а остальное в файле оставит как было, вместе с полями, которых eViSTool не знает. Если файл
испорчен, `setup` его не тронет и скажет, где ошибка.

## agents/<профиль>.automation.json — расписание

Вкладка «Расписание» в окне. Копии мира, перезапуски и обновление модов при перезапуске агент делает сам, окно для
этого держать открытым не нужно.

| Поле | Что это | По умолчанию |
|---|---|---|
| `BackupEnabled` | Делать копии мира по расписанию, пока сервер работает | `false` |
| `BackupIntervalHours` | Раз во сколько часов (дробное число; не чаще раза в 5 минут, не реже раза в 30 дней) | `1` |
| `BackupKeep` | Сколько последних своих копий хранить, `0` — не удалять | `7` |
| `BackupOnlyWhenPlayed` | Пропускать копию, если с прошлой никто не заходил | `true` |
| `BackupAnnounce` | Сообщать игрокам в чат, что копия готова | `true` |
| `BackupDir` | Куда складывать копии (полный путь, можно сетевую папку). Сервер всё равно пишет копию в свою папку `Backups`, а агент потом переносит её сюда | `null`, то есть `Backups` в данных сервера |
| `RestartMode` | `"Off"`, `"Interval"` (каждые N часов работы) или `"Daily"` (в заданное время) | `"Off"` |
| `RestartIntervalHours` | Для `Interval`: через сколько часов работы перезапускать (не меньше 5 минут) | `12` |
| `RestartTimes` | Для `Daily`: времена суток, `["05:00", "17:30"]` | `["05:00"]` |
| `RestartWarnMinutes` | За сколько минут предупреждать игроков (от 1 до 180) | `[10, 5, 4, 3, 2, 1]` |
| `RestartBackup` | Перед перезапуском по расписанию сделать копию мира | `true` |
| `RestartUpdateMods` | Пока сервер стоит при перезапуске, поставить вышедшие обновления модов | `false` |
| `UpdatePinned` | Закреплённые моды, их не обновлять: `{"modid": "версия"}` | пусто |
| `UpdateBlocked` | Пропущенные версии, их не ставить: `{"modid": ["1.2.3"]}` | пусто |
| `UpdateAllowUnstable` | Предлагать пре-релизы | `false` |

`UpdatePinned`, `UpdateBlocked` и `UpdateAllowUnstable` окно переписывает из своих настроек модов, когда сохраняет
расписание. Время везде местное время машины, а у Ubuntu по умолчанию это UTC.

## agents/<профиль>.remote.json — удалённый доступ

По этому файлу агент принимает подключения окна eViSTool с другого компьютера: по TLS, на своём порту, со своим
ключом. Включают и выключают его командой `eViSTool.Agent remote …` или в окне.

| Поле | Что это |
|---|---|
| `Enabled` | Принимать подключения из сети |
| `Port` | Порт TCP. При первом включении выбирается случайно из 20000–60000 и дальше не меняется. Его нужно открыть в брандмауэре |
| `Key` | Ключ удалённого подключения |
| `Host` | Адрес, который попадает в код подключения: IP в локальной сети, внешний IP или домен. Если пусто, берётся первый адрес машины |

Руками можно менять `Enabled`, `Host` и `Port`, агент подхватит правку за несколько секунд. Адрес и порт входят в код
подключения, поэтому после их смены код надо взять заново (`remote code`) и вставить в окно ещё раз.

`Key` руками не правь: ключ короче 32 знаков агент не примет, и удалённый доступ не включится. Новый ключ даёт команда
`remote new-key`; после неё все, кто подключён снаружи, отключатся, и им нужен новый код. Сертификат агента лежит
рядом, в `agents/<профиль>.remote.pfx`. Его тоже не трогай: если удалить файл, агент создаст новый сертификат с другим
отпечатком, и окна, знающие старый код, перестанут подключаться.

В этом файле ключ лежит открытым текстом. Кто его прочитает, сможет управлять сервером, поэтому папка `data` должна
быть доступна только пользователю агента (`setup` создаёт её с правами `700`).

## agents/<профиль>.notify.json — оповещения

Вкладка «Оповещения» окна: какое событие в какие каналы (Telegram, Discord, ntfy, вебхук) отправлять. Секреты каналов
(токен бота, адрес вебхука, тема ntfy) хранятся в поле `SecretProtected` зашифрованными ключом того пользователя, от
которого работает агент. Задавай их из окна: оно передаёт секреты агенту по защищённому соединению, и агент шифрует их
у себя. Строку `SecretProtected`, скопированную с другой машины или от другого пользователя, агент не расшифрует.

Руками можно поправить остальное:

- `ServerName` — имя сервера в заголовках («Survival: сервер упал»). Окно пишет сюда имя профиля. Если поле пустое,
  агент без окна берёт `ServerName` из `agent.json` или из `serverconfig.json`.
- `Routes` — событие и список id каналов: `{"ServerCrashed": ["<id>"]}`. События: `ServerCrashed`, `StartFailed`,
  `BackupFailed`, `LowDisk`, `Overloaded`, `ModsUpdated`, `ModUpdates`, `ServerStarted`, `ServerStopped`,
  `RestartSoon`, `PlayerJoined`, `PlayerLeft`.
- `ChatChannelId` — id канала Discord, куда пересылать общий чат игры (`null` — не пересылать), и `ChatJoins` —
  писать ли туда, кто зашёл и вышел.
- В `Channels` у каждого канала есть `Id`, `Name`, `Kind` (`0` Telegram, `1` Discord, `2` ntfy, `3` вебхук) и поля
  своего вида: `ChatId` и `TopicId` у Telegram, `Url` у ntfy (свой сервер, пусто — ntfy.sh), `Template` у вебхука.

## agents/<профиль>.announcements.json — объявления

Вкладка «Объявления»: сообщения игрокам в чат по расписанию.

```json
{
  "OnlyWithPlayers": true,
  "Items": [
    { "Text": "Карта сервера: map.example.org", "IntervalMinutes": 60, "Enabled": true }
  ]
}
```

`OnlyWithPlayers` — говорить, только если на сервере кто-то есть (по умолчанию `true`). У каждого объявления свой
интервал в минутах, от 1 до 1440 (по умолчанию 30); два объявления в одну минуту не уходят, второе ждёт.

## agents/<профиль>.stats/ — статистика

Раз в минуту агент записывает, сколько игроков на сервере, сколько памяти он занимает и как загружен процессор, а
ещё входы, выходы, запуски и падения. Файл на каждый день (`2026-10-09.log`), хранятся 30 дней.

Сбор включается пустым файлом `enabled` в этой папке, отдельно от расписания. Окно ставит его на вкладке
«Статистика», а руками это делается так:

```sh
sudo -u vintagestory mkdir -p data/agents/server.stats
sudo -u vintagestory touch data/agents/server.stats/enabled   # включить
sudo -u vintagestory rm data/agents/server.stats/enabled      # выключить
```

## Ключ секретов: secret.key

На Linux секреты каналов оповещений (токены, адреса вебхуков, темы ntfy) шифруются ключом пользователя. Он
лежит в `~/.local/share/eViSTool/secret.key` (или `$XDG_DATA_HOME/eViSTool/secret.key`) того, от чьего имени работает
агент, с правами `600`. Если домашней папки у пользователя нет или туда нельзя писать, ключ ложится в `data/secret.key`.

Без этого файла сохранённые секреты не расшифровать. Если переносишь сервер на другую машину, перенеси и ключ, иначе
каналы оповещений придётся задать в окне заново. На Windows файла нет: там секреты шифрует сама система (DPAPI).

## Служебные файлы

Их пишет и читает сам агент, править их не нужно.

| Файл | Что в нём |
|---|---|
| `agents/<профиль>.key` | Ключ, по которому агента зовут окно и команды на этой машине (права `600`). Если удалить, агент создаст новый при запуске |
| `agents/<профиль>.json` | Адрес работающего агента: PID, порт, время запуска, версия. Появляется при запуске и удаляется при выходе |
| `agents/<профиль>.lock` | Замок на Linux: второй агент того же профиля не запустится |
| `agents/<профиль>.after-update` | Работал ли сервер до «Обновить на сервере»: по этой отметке новая версия агента под systemd решает, запускать ли его. Забирается при запуске |
| `agents/<профиль>.remote.pfx` | Сертификат удалённого доступа (см. выше) |
| `agents/<профиль>.commands.json` | Команды сервера из его ответа на `/help`, для подсказок в консоли окна |
| `agents/<профиль>.modupdates.json` | О каких обновлениях модов уже оповещали, чтобы не повторяться |
| `ModConfigBackups/<профиль>/` | Прежние версии настроек модов, сохранённые перед правкой из окна |

`settings.json` и `notify-channels.json` в `data` — настройки самого окна eViSTool. На сервере без окна их нет.
