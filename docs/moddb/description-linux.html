eViSTool on Linux is the same program as on Windows. On a desktop it's a window for your mods and servers. On a server without a desktop it's an agent that looks after the game server around the clock as a systemd service. Both are in one archive: take what you need.

For players: the window

  • Finds the game by itself, whether it's from the archive (installed with install.sh) or from Flatpak. If you have both, each gets its own profile with its own mods.
  • Mod updates in one click, the ModDB catalog with search and filters, modpacks, mod settings as a form, copies of your worlds before mod changes.
  • Share your mods with a code: one line like EV1-… gives your friend the same mods in the same versions from the ModDB, on Linux or Windows.
  • Launches the game, for Flatpak too, and won't touch the mods while the game is running.
  • Manages your servers, local or on another machine, with a connection code.
  • Manages a server rented from a host (G-Portal and others) over FTP or SFTP: mods with one-click "Update all", mod settings, the server log with its state, players and crashes, notifications, and copies of the world on your computer. Starting and stopping stay in the host's panel.

Unpack the zip anywhere in your home folder and run ./eViSTool. On the first start it adds itself to the applications menu. Nothing else to install: the window ships with its own runtime. Tested on Ubuntu 24.04 with GNOME.

For servers: the agent

  • Starts the server with the machine and brings it back after a crash, telling you which mod is most likely to blame.
  • Scheduled world backups with rotation, into any folder, a mounted network share included. Restore with one click.
  • Scheduled restarts: warns players in chat, takes a fresh backup and can install mod updates while the server is down.
  • Notifications to Telegram, Discord, ntfy or any webhook: the server crashed, a backup failed, mod updates are out, the disk is running low, someone joined. The game chat can go to a Discord channel.
  • Chat announcements on a schedule and statistics: who was online, memory and CPU, time played.
  • A journal of who did what with the server: starts, commands, mods, config, backups, and failed connection attempts.

You control it from the eViSTool window on your computer, Windows or Linux, with a connection code: the live console with command hints, the config editor, players and whitelist, mods, mod settings and Update on the server, which updates the agent to your version in one click.

If your server is installed the official way, with server.sh, unpack the zip into its own folder (not into the game folder: the game is updated with rm -rf *) and run:

sudo apt install unzip
sudo mkdir -p /home/vintagestory/evistool
sudo unzip eViSTool-<version>-linux-x64.zip -d /home/vintagestory/evistool
sudo chown -R vintagestory:vintagestory /home/vintagestory/evistool
cd /home/vintagestory/evistool
sudo -u vintagestory ./eViSTool.Agent setup
sudo -u vintagestory ./eViSTool.Agent remote enable --host <address of this machine>
sudo -u vintagestory ./eViSTool.Agent remote code
sudo ./eViSTool.Agent service install

Then paste the code into the window: Profiles → + Server → Server on another computer? → Connect by code… The window file in that folder isn't needed on a server, it just lies there.

The same files are on GitHub as a tar.gz. You'll need Linux x64 with systemd (tested on Ubuntu Server 24.04) and .NET 10 for the game server itself; the agent ships with its own runtime. The step-by-step guide, with ports, day-to-day commands, logs and uninstalling, is on GitHub.

По-русски

eViSTool на Linux — та же программа, что и на Windows. На компьютере с рабочим столом это окно для модов и серверов. На сервере без рабочего стола это агент, который круглые сутки присматривает за сервером игры как служба systemd. Оба лежат в одном архиве, бери что нужно.

Для игроков: окно

  • Само находит игру — из архива (через install.sh) или из Flatpak. Если стоят обе, у каждой будет свой профиль со своими модами.
  • Обновление модов одной кнопкой, каталог модбазы с поиском и фильтрами, модпаки, настройки модов формой, копии миров перед изменением модов.
  • Моды можно передать кодом: одна строка вида EV1-… даст другу те же моды в тех же версиях с модбазы, на Linux или Windows.
  • Запускает игру, в том числе из Flatpak, и не трогает моды, пока игра запущена.
  • Управляет твоими серверами, своими и на другой машине, по коду подключения.
  • Управляет сервером у хостера (G-Portal и другие) по FTP или SFTP: моды с «Обновить всё» в одну кнопку, настройки модов, лог сервера с состоянием, игроками и вылетами, оповещения и копии мира у тебя на компьютере. Запуск и остановка остаются в панели хостера.

Распакуй zip куда угодно в домашней папке и запусти ./eViSTool. При первом запуске он сам появится в меню приложений. Больше ничего ставить не нужно: окно собрано вместе со своей средой. Проверено на Ubuntu 24.04 с GNOME.

Для серверов: агент

  • Запускает сервер вместе с машиной и поднимает после падения, а в оповещении пишет, какой мод скорее всего виноват.
  • Копии мира по расписанию с удалением старых, в любую папку, в том числе подключённую сетевую. Восстановление одной кнопкой.
  • Перезапуски по расписанию: предупреждение игрокам в чате, свежая копия и обновление модов, пока сервер стоит.
  • Оповещения в Telegram, Discord, ntfy или вебхук: упал, копия не получилась, вышли обновления модов, мало места, кто зашёл. Чат игры можно пересылать в Discord.
  • Объявления в чат по расписанию и статистика: онлайн, память и процессор, кто сколько наиграл.
  • Журнал: кто и что делал с сервером — запуски, команды, моды, конфиг, копии и неудачные попытки подключиться.

Управляешь им из окна eViSTool на своём компьютере, с Windows или Linux, по коду подключения: консоль с подсказками, редактор конфига, игроки и белый список, моды, настройки модов и кнопка «Обновить на сервере», которая обновит агента до твоей версии.

Установка — командами выше, если сервер поставлен через server.sh. Файл окна в этой папке серверу не нужен, пусть просто лежит. Те же файлы в tar.gz лежат на GitHub. Подробная инструкция — на GitHub по-русски.
