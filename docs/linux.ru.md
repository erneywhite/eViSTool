# eViSTool на Linux-сервере

[English](linux.md) · **Русский**

Окна eViSTool на Linux пока нет, там работает только агент `eViSTool.Agent`. Он держит сервер Vintage Story: запускает его,
поднимает после падения, делает резервные копии и перезапуски по расписанию, рассылает оповещения. Управляешь им из окна
eViSTool на Windows по коду подключения, как любым удалённым сервером (см. [«Удалённое управление»](../README.ru.md#удалённое-управление) в README). На самой
машине агент ставится службой systemd и поднимается вместе с ней.

## Что понадобится

- Ubuntu или Debian на x64 с systemd. Проверено на Ubuntu Server 24.04.
- Права root (`sudo`).
- .NET 10 для самого сервера Vintage Story. Агенту .NET не нужен: он собран вместе со своей средой.
- eViSTool на Windows, из которого будешь управлять сервером.

## Сервер Vintage Story

Ставь его как обычно, по [официальной инструкции](https://wiki.vintagestory.at/Guide:Dedicated_Server) и скрипту
`server.sh` из архива сервера. Коротко:

```sh
sudo apt install dotnet-runtime-10.0 screen procps
# скачай vs_server_linux-x64_<версия>.tar.gz, распакуй и дальше по инструкции:
sudo ./server.sh setup
```

`server.sh setup` заводит системного пользователя `vintagestory`, папку игры `/home/vintagestory/server` и папку данных
`/var/vintagestory/data` (мир, конфиг, моды, логи). Пути зашиты в начале `server.sh`, агент читает их оттуда сам.

Сервер, запущенный через `server.sh`, останови до установки службы: дальше его запускает агент. Если запустить ещё и
`server.sh start`, на одном мире окажутся два сервера.

## Куда положить eViSTool

В отдельную папку рядом с сервером, например `/home/vintagestory/evistool`. В папку игры класть нельзя: игру обновляют
командой `rm -rf *` в её папке, и eViSTool пропал бы вместе с настройками. Настройки агента живут в папке `data` рядом
с ним, как и на Windows.

## Установка

### 1. Скачать и распаковать

Архив `eViSTool-<версия>-linux-x64.tar.gz` лежит на [странице модбазы](https://mods.vintagestory.at/evistoollinux) и на странице
[Releases](https://github.com/erneywhite/eViSTool/releases). Внутри один исполняемый файл `eViSTool.Agent` и документы.

```sh
cd /tmp
wget https://github.com/erneywhite/eViSTool/releases/download/v0.10.0/eViSTool-0.10.0-linux-x64.tar.gz
sudo mkdir -p /home/vintagestory/evistool
sudo tar -xzf eViSTool-0.10.0-linux-x64.tar.gz -C /home/vintagestory/evistool
sudo chown -R vintagestory:vintagestory /home/vintagestory/evistool
cd /home/vintagestory/evistool
```

`chown` обязателен. Агент работает от пользователя `vintagestory`, владельца данных сервера, и пишет в свою папку
настройки, ключи и при обновлении новые файлы.

### 2. От чьего имени запускать команды

Все команды, которые меняют настройки агента, запускай от `vintagestory`: `sudo -u vintagestory ./eViSTool.Agent …`.
Секреты (токены оповещений и прочее) агент шифрует ключом того пользователя, от которого работает. Ключ лежит в
`/home/vintagestory/.local/share/eViSTool/secret.key`, и служба работает с тем же ключом. Если запустить команду от
root, папка `data` может стать собственностью root, и служба не сможет в неё писать. `service install` это заметит и
подскажет, какой `chown` выполнить.

Только `service install` и `service uninstall` запускаются от root: они пишут в `/etc/systemd/system`.

### 3. Найти сервер

```sh
sudo -u vintagestory ./eViSTool.Agent setup
```

Агент находит сервер рядом с собой или по `server.sh`, запоминает его папки (`data/agent.json`) и проверяет права. Если
сервер стоит в другом месте, укажи папки сам: `--game /путь/к/игре --data /путь/к/данным`.

### 4. Удалённый доступ

```sh
sudo -u vintagestory ./eViSTool.Agent remote enable --host 203.0.113.5
sudo -u vintagestory ./eViSTool.Agent remote code
```

В `--host` укажи адрес, по которому до этой машины достучится твой компьютер с Windows: в домашней сети локальный
(вроде `192.168.1.20`), из интернета внешний IP или домен. Адрес попадает в код подключения, поменять его можно позже
командой `remote host <адрес>`.

`remote code` печатает код подключения. В нём адрес, порт, ключ и отпечаток сертификата сервера, поэтому обращайся с ним
как с паролем. Если код утёк, `remote new-key` сменит ключ, и старый код перестанет работать.

В окне eViSTool на Windows: «Настройки» → «+ Сервер» → «Сервер на другом компьютере?» → «Подключить по коду…», вставь
код, нажми «Проверить подключение» и создай профиль.

### 5. Порт удалённого доступа

Порт агент выбирает случайно (от 20000 до 60000) при первом `remote enable` и дальше не меняет. Узнать его можно командой
`sudo -u vintagestory ./eViSTool.Agent remote status`. Если на машине включён межсетевой экран, открой порт:

```sh
sudo ufw allow 44731/tcp     # твой порт из remote status
```

Соединение зашифровано (TLS), а без ключа из кода агент ничего не делает. Выставлять порт в интернет всё равно лучше не
стоит: надёжнее зайти на машину через VPN (WireGuard, Tailscale) и подключаться по её адресу в VPN. Если без интернета не
обойтись, пробрось порт на роутере.

Порт самой игры для игроков (`42420`, TCP и UDP) от этого не зависит, его открываешь как обычно.

### 6. Служба systemd

```sh
sudo ./eViSTool.Agent service install
```

Команда проверяет, что пользователь службы может читать игру, писать данные сервера и папку eViSTool, записывает юнит
`/etc/systemd/system/evistool.service`, включает его и запускает. Агент в службе работает от владельца данных сервера
(обычно `vintagestory`) и сразу запускает сервер. В конце команда пишет, что получилось:

```
Служба evistool установлена и работает.
  агент: /home/vintagestory/evistool/eViSTool.Agent, пользователь vintagestory, PID 93562
  сервер: /home/vintagestory/server, данные: /var/vintagestory/data
  сервер запускается вместе со службой (PID 93580)
После перезагрузки машины служба поднимется сама.
Журнал: sudo journalctl -u evistool -f
```

Ключи, если понадобятся:

- `--user <имя>` запускает агента от другого пользователя. Без ключа это владелец данных сервера. Если всё принадлежит
  root, команда попросит назвать пользователя: молча запускать сервер от root она не станет.
- `--name <имя>` даёт службе другое имя, например для второго сервера на той же машине (у него своя папка eViSTool).
- `--lang ru` или `--lang en` задаёт язык сообщений агента, которые видны в окне eViSTool, и объявлений игрокам. Без
  ключа агент говорит на языке системы.
- `--game` и `--data`, если сервер лежит не там, где его находит агент.

Повторный `service install` безопасен. Если настройки те же, он ничего не меняет. Если другие, перезапускает службу:
сервер остановится с сохранением мира и запустится снова.

## Каждый день

Сервером управляешь из окна eViSTool. На самой машине есть те же основные команды:

```sh
sudo -u vintagestory ./eViSTool.Agent status            # что с сервером
sudo -u vintagestory ./eViSTool.Agent stop              # остановить сервер, мир сохранится
sudo -u vintagestory ./eViSTool.Agent start
sudo -u vintagestory ./eViSTool.Agent restart
sudo -u vintagestory ./eViSTool.Agent command "/time"   # команда серверу
```

Они идут через работающего агента: `stop` останавливает только сервер, агент остаётся и окно к нему подключается. После
перезагрузки машины служба снова запустит и сервер.

Служба целиком:

```sh
./eViSTool.Agent service status        # установлена ли, включена ли, работает ли и от кого
systemctl status evistool
sudo systemctl stop evistool           # агент остановит сервер с сохранением мира, обычно за секунды
sudo systemctl start evistool
sudo systemctl restart evistool
```

На остановку systemd даёт пять минут: большой мир сохраняется долго. Что не закончилось за это время, systemd завершит
принудительно.

### Журналы

`sudo journalctl -u evistool -f` показывает журнал агента: где он нашёл сервер, на каком адресе слушает, почему не
запустился. Туда же идёт консоль сервера. Журнал самого сервера лежит в его данных: `/var/vintagestory/data/Logs/server-main.log`. Консоль сервера
видна в окне eViSTool.

### Если что-то упало

Если упал сервер, агент поднимет его сам, как и на Windows. Если упал сам агент или его убили (`kill -9`), systemd сразу
завершает и сервер, без сохранения, а через пять секунд запускает агента заново, и тот запускает сервер. Пропадёт то,
что сервер не успел сохранить сам, поэтому останавливай службу через `systemctl stop` или командой `stop`.

Если агент падает раз за разом (пять запусков за пять минут), systemd перестаёт его поднимать и пишет, что служба упала.
Причину покажет `sudo journalctl -u evistool`. Когда исправишь, запусти службу снова:

```sh
sudo systemctl reset-failed evistool
sudo systemctl start evistool
```

## Обновление eViSTool

Проще всего из окна eViSTool на Windows: когда у тебя версия новее, на вкладке «Сервер» появляется кнопка «Обновить на
сервере». Агент скачивает архив той же версии с GitHub, сверяет контрольную сумму, останавливает сервер с сохранением мира,
заменяет свои файлы и выходит, а systemd запускает новую версию. Если сервер работал, он запустится снова, если был
остановлен, то останется остановленным.

Вручную: остановить службу, распаковать новый архив поверх старого и запустить. Папки `data` в архиве нет,
настройки остаются.

```sh
sudo systemctl stop evistool
sudo tar -xzf eViSTool-<версия>-linux-x64.tar.gz -C /home/vintagestory/evistool
sudo chown -R vintagestory:vintagestory /home/vintagestory/evistool
sudo systemctl start evistool
```

## Обновление игры

`server.sh` советует остановить сервер, очистить папку игры (`rm -rf *`), распаковать новый архив и вернуть
`server.sh`. С eViSTool всё так же, только вместо остановки сервера останавливай службу:

```sh
sudo systemctl stop evistool
# обновление игры по инструкции server.sh
sudo systemctl start evistool
```

eViSTool лежит в своей папке, обновление игры его не задевает.

## Удаление

```sh
sudo /home/vintagestory/evistool/eViSTool.Agent service uninstall
sudo rm -rf /home/vintagestory/evistool
sudo rm -rf /home/vintagestory/.local/share/eViSTool /home/vintagestory/.net/eViSTool.Agent
```

`service uninstall` останавливает агента и сервер (мир сохраняется) и убирает службу. Вторая строка удаляет eViSTool с
его настройками, третья — ключ секретов и распакованные библиотеки агента. Сервер и мир остаются на месте. Если
открывал порт удалённого доступа, закрой его: `sudo ufw delete allow 44731/tcp`.

## Если не получается

`service install` пишет, что мешает и что сделать:

- Если пользователю службы не хватает прав, команда напечатает `chown`, который отдаст ему папку.
- Если агент этого профиля уже работает не как служба, останови его (Ctrl+C в его терминале или `kill <PID>`).
- Если сервер этого мира уже запущен без агента, останови его так же, как запускал: `server.sh stop` или `/stop` в его
  консоли.
- Если имя `evistool` занято чужой службой, возьми другое через `--name`.

Окно на Windows не подключается — проверь `remote status` (включён ли доступ, какой порт), открыт ли порт в межсетевом
экране и на роутере и подходит ли адрес из кода к тому, откуда подключаешься: локальный адрес работает только внутри
той же сети.

Какие файлы хранит агент и что в них — в [описании настроек](config.ru.md).
